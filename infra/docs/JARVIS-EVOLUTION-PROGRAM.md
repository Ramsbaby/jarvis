## 한 줄 결론

**이 프로그램의 전부는 한 문장이다: "자비스가 자기 완료를 자기가 채점하지 못하게 만든다."**
오늘 감사가 증명했다 — 자비스가 "근본수정 완료"라 선언한 proactive 수정은 실제로 반쪽(불안정 키)이었고,
독립 감사관이 CRITICAL 결함을 적발했다. 텍스트 룰 20겹으로도 못 막은 이 편향을, **실측 게이트로 구조화**한다.

핵심 발견 (설계를 바꾼 것):
- **바퀴를 다시 만들 뻔했다.** North Star 채점기·주간 스코어카드·자기평가 루프는 **이미 만들어져 크론으로 돈다**
  (`north-star-audit.mjs` 월 09:20, `self-evolution-weekly.sh` 월 09:30, `improvement-scorecard-measure.mjs`).
  → 이 프로그램은 **신규 개발이 아니라 기존 채점기의 빈 3개 구멍**(자동차단 트리거·독립검증 게이트·누락 지표)만 메운다.

## §1. 산출물 1 — North Star 조작화 (측정 가능한 신뢰 지표 + 실측 baseline + 목표)

### North Star의 정의
> **위임 가능 = 주인님이 안 봐도 되는 것.** "화려함"이 아니라 "안 봐도 되는가"가 유일한 척도.

이것을 **6개 세부 신뢰 지표**로 분해한다. 각 지표는 "이것이 나쁘면 주인님이 자비스를 다시 확인해야 한다"는
한 문장으로 검증된다. **3개는 이미 채점 중**(`north-star-audit.mjs`), **3개는 미포함 → 기존 채점기에 추가**.

### 지표 · 실측 baseline · 목표

| # | 지표 | "안 봐도 되는가?" 해석 | 소스 원장(실측) | 현재 baseline | 목표 | 채점 상태 |
|---|---|---|---|---|---|---|
| 1 | **거짓완료 건수** | `section0-violation.jsonl` (evidence_gate+audit_gate) | 완료검증 게이트 위반 누적 **176건**(audit 100+evid 76), 최근7일 **17건** | 신규 하락·0 지향 | ❌ **미채점** — trust축은 `violations`(§0질문)만 합산, 거짓완료는 0 기여(감사 B3 확정) |

**종합 지표 = `north-star-audit.jsonl`의 overall 점수.** 실측 이력: 최근 **42점**(7/20), 6주간 **19~58 범위 변동**.
→ **목표: 지속 ≥ 60점** (신뢰는 최고점이 아니라 바닥의 안정성 — 변동성 자체가 문제).

### ⚠️ 최대 발견 — 측정 공백 (이게 산출물 1의 진짜 1순위 · 감사로 정정됨)
**6지표 중 2개(오알림률·재작업률 직접)는 측정경로 자체가 없다.** (초안은 "3개"였으나 감사 B2가 응답지연을
정정 — 이미 측정중.) 라벨 없는 지표에 목표값을 붙이는 건 R5 재발("재현율 미측정 상태의 성급한 단정")이다. 따라서:
- 산출물 1의 1순위 = **"목표값 설정"이 아니라 "측정 계기 신설"**. 계기 없이 목표는 허구.
- **오알림률**: proactive 발화에 "필요했나" 사후 라벨(후속 반응 신호)을 붙이는 최소 계기 필요. `proactive-frequency.jsonl`은 사실상 빈 파일.
- **재작업률**: 직접 재시도 이벤트가 없어 requirement 검증실패(73.9%)를 프록시로만 씀 — 프록시임을 못 박고 직접 계기는 후순위.
- **응답지연 [감사 B2 정정]**: 미측정 아님. `response-ledger.jsonl`(**state/**)에 `elapsed_s` 4,326건 이미 존재(중앙값 ~69초).
  → "duration_ms 신규 추가"는 **이미 있는 데이터 중복**이므로 폐기. 집계만 하면 됨. 채점기가 이 원장을 안 읽는 게 문제.
- 정직: **이 2개(오알림률·재작업률 직접)는 baseline "없음"이 정답이다.** 없는 걸 있다고 쓰지 않는다.
- 주의(감사 교차검증): `section0-violation`의 `violation`(293건)은 §0 불필요질문이지 거짓완료가 아니다 → 거짓완료 프록시는 `evidence_gate`+`audit_gate`만 사용. **그리고 이 둘은 현재 어느 채점기에도 안 들어간다(B3) → 지표1은 미채점.**

### 왜 이 6개인가 (1차 원리)
"안 봐도 되는가"는 3개 실패 모드로만 깨진다: **(a) 거짓말한다**(1·6) → **(b) 헛짓한다**(2·3·4) → **(c) 느리다**(5).
이 3×2 격자가 신뢰의 전부다. 능력(멀티모달·음성)은 여기에 없다 — **능력은 신뢰의 조건이 아니라 신뢰가 허락하는 결과**.

## §2. 산출물 2 — 능력 머지 게이트 (코드화 · 자기 PASS 금지)

**어떤 능력 PR/기능도 머지 전 4조건을 전부 통과**해야 한다. 하나라도 미충족 시 머지 차단.

```
capability-merge-gate  (BLOCKING 체크리스트 + 얇은 검증기)
 ① 가역성 분류    비가역(외부송출·삭제·visibility·결제·크론일괄) → 주인님 결재 필수
                  재사용: precheck-dangerous.sh + Iron Law 3
 ② 원장 등재      변경을 append-only 원장에 기록 (누가·무엇·왜·롤백경로)
                  재사용: disable-plist-with-ledger.sh / policy-fix-disable 패턴
 ③ 안정키 상태    per-entity 1회성 상태를 불변 식별자 키로 (휘발성 값 금지)
                  재사용: lib/state-dedup (산출물 5)
 ④ 독립 검증      자기 통과 금지. VERA(jarvis-verify-independent.sh) 또는 /verify Agent가
                  independent-verify.jsonl에 verdict=CONFIRMED(exit 0) 기록해야만 통과.
                  ⚠️[감사 B1] 이 원장의 판정값은 CONFIRMED/REFUTED/UNCERTAIN/VERIFY_FAILED —
                  "PASS"는 방출되지 않음. 게이트는 반드시 CONFIRMED를 기다려야 함(존재하는 값).
                  제출자 주장 = 증거가치 0.
```

### 게이트④가 왜 필수인가 — 오늘의 증거를 박는다
> **2026-07-22**: 자비스가 proactive dedup을 "해시 근본수정 완료, CJ 재질문 0"이라 자가선언.
> 독립 감사관이 실측하니 — (1) CJ를 막는 건 해시가 아니라 owner가 수기 입력한 결과마커였고,
> (2) state의 `d58f67908590`은 실제로는 다른 태스크의 해시였으며(제출자가 자기 코드의 방어 경로조차 오인),
> (3) 해시 입력이 gog 전체 라인이라 메타 1회 변경에 재스팸. **자기검증이었으면 전부 통과됐을 것.**
> → 게이트④ 없이는 "완료"가 곧 "미완료"다. **자기 채점을 구조적으로 금지**하는 유일한 장치가 이 게이트다.

### 구현 (과잉공학 금지)
무거운 CI를 만들지 않는다. `capability-merge-gate.sh`는 **얇은 확인기**:
- ③ = 변경 파일에 휘발성 키(md5(timestamp/전체라인)) 패턴 grep → 발견 시 경고.
- ④ = 해당 변경에 대한 `independent-verify.jsonl` **CONFIRMED** 레코드 존재 확인 → 없으면 차단. (PASS 아님 — B1)
- ①② = 사람이 답하는 BLOCKING 체크리스트 4줄.
- 위반 시 exit 2 (precheck-dangerous.sh와 동일 관례).

## §3. 산출물 3 — 주간 신뢰 스코어카드 (집계만 · DRY · 임계 초과 시 자동차단)

### 현실: 집계기는 이미 있다. 없는 건 "자동차단 트리거" 하나다.
- `north-star-audit.mjs` — 3축 종합 채점, 기존 원장만, LLM 0회, DRYRUN 가드. **월 09:20 가동중.**
- `improvement-scorecard-measure.mjs` — 6지표 계기판(독립검증·bot-bus·promoter·discord-send 집계). **가동중.**
- `self-evolution-weekly.sh` — 학습 4지표 주간 retro. **월 09:30 가동중.**

→ **신규 스코어카드를 만들지 않는다.** `north-star-audit.mjs` 출력 뒤에 **임계 판정 + 자동차단 단계**만 붙인다(~30줄).

### 자동차단 설계 (기존 패턴 재사용)
```
north-star-audit.mjs 채점 완료 후:
  for each 지표 in 화이트리스트(사전 명시된 선제기능만):
    if 추세악화(연속 N주 하락) 또는 분산이상(평균±2σ 이탈):    # ← 절대 임계 아님(RR2)
      disable-plist-with-ledger.sh <매핑된 plist> "스코어카드: <지표> 추세악화 <값>" "auto-disable"
      discord_route critical "<지표> 추세 악화 — <기능> 자동 정지"
```
- **RR2 반영 — 절대 임계 금지**: overall은 19~58로 진폭이 커서 절대값 임계는 정상 변동에 오발한다.
  → **추세(연속 하락) + 분산(평균±2σ)** 기반만 사용. 단발 스파이크로 안 끈다.
- **RR3 반영 — 대상 plist 화이트리스트 필수**: "어떤 지표 악화 → 어떤 plist를 끈다"를 사전 명시(예: 오알림률↑ → `com.jarvis.proactive-engine`). 매핑에 없는 지표는 알림만, 자동차단 안 함. 오탐 시 무엇이 꺼지는지 불확정한 상태 금지.
- **가드 (BLOCKING)**: 자동차단은 반드시 **가역**(bootout + `.disabled` rename, 삭제 금지) + **원장 등재** + **재활성은 주인님 결재**. `policy-fix-disable` 패턴 그대로.
- **1주 DRYRUN 먼저**: 임계 로직을 로그만 남기고 실제 차단은 안 하는 모드로 1주 관측 → 오탐 없으면 활성(CRON-INTRODUCTION-CHECKLIST 준수).

## §4. 산출물 4 — 자기구동 루프 (매주: 최악 결함 1개 → 근본수정 → 독립검증 → 오답노트)

### 현실: 집계는 있으나 루프가 안 닫혀 있다. 닫는 매듭 = 독립검증 게이트.
`self-evolution-weekly.sh`는 학습 수치를 모으지만 **"고른다→고친다→검증한다→배운다"를 닫지 않는다.**
이 프로그램이 그 루프를 정의한다. 단 **완전 무인 자동수정은 금지**(코드 변경 = 비가역 위험 = 주인님 결재).

```
자기구동 루프 (주간 · 반자율)
 1. 선정 (자동)      스코어카드에서 "이번 주 신뢰를 가장 깎은 지표 1개" 자동 선택.
                     원장 기반 정렬만 — LLM·추측 0. (최저점 또는 최악 추세)
 2. 근본수정 (세션)  5 Why + 미니멀 diff. 능력 머지 게이트(§2) 통과 전제.
 3. 독립검증 (필수)  VERA 또는 독립 Agent가 재검증. 자기 통과 금지.
                     independent-verify.jsonl에 verdict=CONFIRMED 기록돼야 "수정 완료"로 인정(B1: PASS 아님).
 4. 오답노트         learned-mistakes.md에 교훈 + "독립검증이 자기검증을 뒤집었는가" 기록.
```

### 오늘의 proactive = 이 루프의 첫 실행이자 표준 템플릿
- 1(선정): "완료면접 8일 스팸"이 신뢰를 가장 깎는 결함으로 선정됨. ✅
- 2(수정): 해시 dedup + 결과마커 스킵. ✅
- 3(독립검증): 감사관이 "근본수정" 자가선언을 **뒤집음** → CONDITIONAL·CRITICAL R1. ✅ ← **이 루프의 존재 이유를 실증**
- 4(오답노트): "안정키를 휘발성 값으로 만들면 근본수정 아님" 등재.
→ **"독립검증이 자기검증을 뒤집은" 이 사이클을 그대로 표준 템플릿으로 박는다.**

### 가드
- 루프는 **선정·진단까지 자율**(안전), **수정·머지는 게이트→주인님 결재**(비가역 보호).
- 무인으로 프로덕션에 코드를 밀어넣지 않는다. Iron Law 3.

### ⚠️ 정직한 경계 (과대클레임 방지)
proactive-engine.sh는 **bash 안에 Python이 박힌** 구조(`import hashlib`)라 `.mjs`를 직접 import 못 한다.
→ 공용화되는 것은 "한 파일"이 아니라 **(a) 상태 스키마 + (b) 키 안정성 계약**이며, JS 호출자용 얇은 lib 1개 + Python 참조구현(proactive)으로 나뉜다. "50줄 파일 하나가 3곳을 다 막는다"는 과장이다.

```
lib/state-dedup.mjs  (신규 ~50줄 · JS 호출자용)
  seen(namespace, entityKey) -> bool     // 이미 처리했나
  mark(namespace, entityKey, meta)       // append-only 기록
  // 저장 = 기존 state json/JSONL 확장 (신규 인프라 0)
  // ⚠️ entityKey는 호출자가 '불변 식별자'로 만들어 넘길 책임 — lib은 안정성을 강제 못 함
```

### 적용처별 "안정 키"가 무엇인가 (BLOCKING — 반드시 엔티티 불변 ID)

| 적용처 | 안정 키 (entityKey) | 근거·주의 |
|---|---|---|
| **proactive 체크2** | **gog task ID** (예: `U3ZVaFY2cmVZUlZMczdybQ`) | 실측: `gog tasks list` 첫 컬럼 = 22자 불변 ID ✓. 현재 코드는 표시라인 첫 토큰 파싱(작동하나 취약). **fallback md5(title)는 휘발성 → 제거.** 단 [RR1] 무작정 제거 대신 **① `gog tasks list --json`으로 ID 재취득 시도 → ② 그래도 no-ID면 발송 스킵 + 그 사실을 원장 기록**(정당한 알림 영구침묵을 관측 가능하게) |
| **오답노트 promoter** | **md5(정규화 교훈 패턴문)** | 엔티티=실수 패턴. 정규화=소문자·공백압축·문장부호제거. ⚠️ **현재 promoter는 report_only(쓰기 OFF, 7/19~)** — 이 적용은 쓰기 재개 시에만 유효. "지금 버그를 고친다"가 아님 |
| **세션 재질문** | **md5(질문대상 엔티티 + 결과상태)** | 예: `md5("면접태스크-결과|탈락")`. 엔티티=특정 결정+해결상태. "탈락인데 또 물어봐" 원천 차단 |
