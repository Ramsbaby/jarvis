## 한 줄 결론 (1차 원리)

**진짜 JARVIS는 화려한 능력이 아니라 "신뢰"다.** 4명의 조사관이 독립적으로 같은 뿌리에 도달했다:

> **反JARVIS의 근본 = "상태 없음(statelessness)".** 이미 처리한 걸 기억 못 해서 스팸이 난다.
> proactive 8일 스팸 · 오답노트 15중복 · "탈락인데 왜 또 물어봐" — **전부 같은 병의 세 증상.**

→ 로드맵 = **① 신뢰 부채 청산 + ② 이미 만든 것 살리기**. "새 기능 추가"가 아니다.

### North Star — "완성"의 정의
> **주인님이 Jarvis에게 진짜 판돈(오퍼 결정·자산·서류·일정)을 맡기고, 다시 확인하지 않아도 되는 상태.**
> = 위임 가능(delegatable) = 신뢰의 조작적 정의. 화려함이 아니라 "안 봐도 되는 것"이 지표다.

## §2. 왜 이 순서인가 (신뢰 > 능력)

1. **신뢰 손상은 비가역, 능력 부재는 가역.** 스팸 10일·가족채널 오발송(6/12)·Chrome 세션 강제종료(7/14)는 이미 겪음. 신뢰가 깨지면 주인님이 자율성 권한을 회수 → 계층1·2 전부 무의미.
2. **능력↑ = 신뢰 결함 폭발반경↑.** 브라우저 자가우회(봇이 화이트리스트를 스스로 Edit·7/21 실측)를 게이트 없이 두면 실제 결제·삭제로 확대.
3. **완성도 ≠ 가동률.** 제일 공들인 것(v2 5패턴·음성·브라우저 자율)이 정확히 비활성·휴면·거짓보고. 매일 돕는 건 못생긴 v1·SQLite 원장·RAG. **"만들었다"가 "돈다"를 담보하지 않는다.**

## §3. 키스톤 설계 — 공용 dedup 상태 레이어 (0-1, 구체)

로드맵 전체의 병목이자 최고 레버리지. proactive 07-22 수정을 **공용 함수로 승격**해 스팸 3종을 한 구조로 잡는다.

```
lib/state-dedup.mjs  (신규, ~50줄)
  seen(namespace, entityKey) -> bool      // 이미 처리했나
  mark(namespace, entityKey, meta)        // 처리 기록 (append-only)
  // 키 = md5(정규화된 엔티티 식별자)[:12]. 저장 = 기존 state json/JSONL 확장(신규 인프라 X)
```

| 적용처 | entityKey | 효과 |
|---|---|---|
| proactive-engine 체크2 | `task_complete_{md5(title)}` | 완료 태스크 최초 1회만 (이미 적용, 이 패턴이 원형) |
| 오답노트 promoter | `md5(정규화 패턴문)` | 15중복·349건 팬아웃 append 차단 |
| 세션 재질문 | `md5(질문대상 엔티티+결과상태)` | "탈락인데 또 물어봐" 원천 차단 |

**측정**: 중복 발화/append 건수 → 0. **리스크**: 낮음(가역, 기존 state 확장). **왜 keystone**: 계층1의 진짜 선제성(1-1)·앰비언트(1-4)가 전부 "이미 알림/처리 여부"에 의존하므로 이게 없으면 그 위가 다시 스팸이 됨.

## §5. 실행 계획 (의존성·크리티컬 패스·타임라인)

**크리티컬 패스**: `0-1 공용 dedup → 0-2 거짓완료 게이트 → (1-1 선제성 · 1-4 앰비언트 · 2-2 자율성)`
→ **0-1이 전체의 관문.** 이것 없이 계층1 선제성을 켜면 다시 스팸.

```
의존성 그래프
  0-1 ──┬─→ 0-3
        ├─→ 1-1 ──→ (선제성 활성)
        ├─→ 1-3
        └─→ 1-4 ──→ (앰비언트)
  0-2 ──┬─→ 1-3
        └─→ 2-2
  0-5 ──→ 2-2
  1-2(음성) ── 독립, 언제든 병렬
```

**타임라인 (공수 S=~2일 / M=~1주 / L=~2~3주)**
- **주 1~2 (계층0 집중)**: 0-1(M)·0-3(S, 0-1재사용)·0-4(S)·0-2(M) 병렬. → "봇이 조용해짐" 체감.
- **주 3~4**: 0-5(M) + 계층1 착수 준비. 1-2 음성 부채상환(Piper→Kokoro)은 이때 병렬 가능.
- **월 2~4 (계층1)**: 1-1 선제성(0-1·0-2 완료 후) → 1-4 앰비언트 → 1-3 브라우저 2단계.
- **월 4~6+**: 1-2 완성 + 계층2 진입.

**즉시 착수 순서 (이번 주 Top-3)**
1. **0-1 공용 dedup 레이어** + proactive 라이브 검증(7/23 09:00 실동작 확인 — "미검증"을 "검증"으로 닫기).
2. **0-3 오답노트 팬아웃 배수** (0-1 재사용, 자기개선 기계의 최대 신뢰부채 종료).
3. **0-4 죽은 유물 판정** (죽은 크론 4종·v2·음성 [부활/삭제] 주인님 결재).
