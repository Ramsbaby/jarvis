# 기술 검토: 에이전트 토큰 예산 가드 (ADR-013)

작성일: 2026-07-02
상태: 완료 (구현됨)
관련 파일: `~/jarvis/infra/lib/token-budget-guard.mjs`

---

## 1. 도입 판단 근거

### 문제 정의

Jarvis 에이전틱 루프는 태스크별로 Claude API를 반복 호출한다. 루프가 복잡한 추론을 수행하거나 예외 상황에서 재시도를 반복할 경우, 단일 태스크가 수백만 토큰을 소비하는 비용 폭주가 발생할 수 있다. 이는 업계 공통 이슈로, 2025년 이후 오픈소스 에이전트 프레임워크(LangChain, AutoGen 등)에서도 동일 패턴이 보고됨.

### 도입 필요성

| 구분 | 미도입 시 위험 | 도입 후 효과 |
|------|--------------|-------------|
| 비용 통제 | 태스크 1건이 일일 예산 전체 소진 가능 | 태스크별 상한으로 격리 |
| 운영 안정성 | 루프 버그 시 무한 소비 | 조기 종료로 피해 제한 |
| 가시성 | 어느 태스크가 비용을 유발하는지 불명확 | JSONL 감사 원장으로 추적 |
| 운영자 대응 | 사후 청구서 확인 후 대응 | 실시간 경고 → 선제 대응 |

### 결정 사항

기존 `token-ledger.jsonl` 인프라를 재사용하여 별도 외부 의존성 없이 구현. Claude Code SDK의 `--budget-tokens` 옵션과 병행 운영하여 이중 가드 체계를 구성한다.

## 2. 임계값 설정 기준

### 태스크별 예산 (`maxBudgetUsd`)

기본값: **$1.00 USD**

설정 근거:
- Jarvis 일반 크론 태스크(system-health, daily-summary 등)의 실측 평균 비용: $0.05–$0.20
- 기본값 $1.00은 평균의 5–20배 여유를 두어 정상 태스크를 차단하지 않음
- 개별 태스크는 `tasks.json`의 `maxBudget` 필드로 재정의 가능

### 일일 전체 누적 상한 (`dailyCapUsd`)

기본값: **$10.00 USD**

설정 근거:
- Jarvis의 일반 운영일 예상 총비용: $1–$3
- $10는 3–10배 여유를 제공하며, 비용 폭주 상황(루프 버그 등)에서 손실을 제한함
- 환경변수 `JARVIS_DAILY_CAP_USD`로 오버라이드 가능

### 경고 임계값 (`warnThreshold`)

기본값: **80%**

- 예산의 80% 도달 시 stderr에 경고 출력 (프로세스 중단 없음)
- 운영자가 선제적으로 개입할 수 있는 시간 확보

### 환경변수 오버라이드

```bash
JARVIS_MAX_BUDGET_USD=0.5   # 태스크별 상한 (USD)
JARVIS_DAILY_CAP_USD=5.0    # 일일 전체 상한 (USD)
```

## 3. 아키텍처

```
ask-claude.sh
  │
  ├─ (실행 전) check 호출
  │     node token-budget-guard.mjs check --task <id> --max-budget <usd>
  │     └─ 초과 시: exit 2 → ask-claude.sh가 조기 종료
  │
  ├─ claude API 호출 (--budget-tokens 옵션)
  │
  └─ (실행 후) token-ledger.jsonl에 비용 기록
```

### 종료 코드 구분

| 코드 | 의미 |
|------|------|
| 0 | 정상 완료 |
| 1 | 일반 오류 (버그, 환경 문제 등) |
| 2 | **예산 초과 조기 종료** (BudgetExceededError) |
| 124 | 타임아웃 (timeout 명령어 표준) |

종료 코드 2를 별도 구분하여 스프린트 계약 검증 및 알림 시스템에서 "비용 초과"를 다른 오류와 구별할 수 있다.

## 4. 리스크 및 완화 방안

### 4-1. 정상 태스크 오탐 차단

**리스크**: 임계값이 너무 낮아 정상 실행 중인 태스크가 조기 종료됨.

**완화**:
- 기본값을 실측 평균의 5–20배로 설정 (오탐률 최소화)
- tasks.json의 `maxBudget` 필드로 태스크별 재정의 지원
- 80% 경고를 통해 임계값 조정 전 운영자에게 사전 알림

### 4-2. token-ledger.jsonl 데이터 누락

**리스크**: 레저 파일이 없거나 손상된 경우 가드가 올바르게 작동하지 않을 수 있음.

**완화**:
- 레저 파일 부재 시 비용 0으로 간주하여 태스크를 허용 (fail-open 정책)
- 손상된 줄은 개별 스킵 처리 (파싱 오류가 전체 집계를 중단시키지 않음)

### 4-3. 시계열 집계 창 불일치

**리스크**: `windowHours=24` 기준으로 누적하므로, 태스크가 자정 기준으로 분리될 경우 일부 비용이 집계에서 제외될 수 있음.

**완화**:
- 일별 한도는 달력 일자 기준이 아닌 "최근 24시간 슬라이딩 윈도우" 방식으로 동작 → 자정 리셋 문제 없음
- 태스크별 예산도 동일하게 24시간 슬라이딩 윈도우 적용

### 4-4. 다중 에이전트 동시 실행 시 경쟁 조건

**리스크**: 여러 에이전트가 동시에 레저를 읽을 경우 일일 합산이 일시적으로 부정확할 수 있음.

**완화**:
- 레저 기록은 `appendFileSync` (원자적 추가) 사용
- 가드 체크는 실행 직전 단일 시점 스냅샷 → 경쟁 조건 발생 확률 최소화
- 수십 ms 내 중복 허용은 허용 오차 범위 내 (실제 비용 영향 미미)

## 6. 결론

토큰 예산 가드는 Jarvis 에이전틱 루프의 비용 폭주 방지를 위한 필수 안전장치다. 기존 인프라(`token-ledger.jsonl`)를 재사용하여 외부 의존성 없이 구현되었으며, fail-open 정책으로 정상 운영을 방해하지 않는다. 임계값은 실측 데이터 기반으로 충분한 여유를 두어 설정되었으며, 환경변수로 유연하게 조정 가능하다.
