## 0. 결론 (3줄)

1. **전면 대체는 권고하지 않는다.** 자비스의 실가치는 코드가 아니라 5개월 축적물(위키·RAG·오답노트 4,752건·페르소나·가드)과 "직접 설계했다"는 커리어 서사인데, 대체 시 이 둘이 가장 크게 훼손된다.
2. **다만 헤르메스는 무시할 수준이 아니다.** 출시 5개월 만에 GitHub 21만 스타, 월 1,700커밋 — 기능 발전 속도는 개인 개발이 절대 못 따라간다. **"기능은 차용, 기반은 유지"**가 최적해다.
3. 병행 실험(격리 VM에 비민감 태스크만) → 분기별 재평가를 권고. 반증 조건(§9)이 발생하면 이 결론은 뒤집힐 수 있다.

## 1. 메타인지 고지 — 이 분석의 편향 위험

**① 이해충돌**: 이 보고서의 작성자(Jarvis)는 Anthropic Claude 위에서 동작하며, 현 자비스 생태계의 엔진이자 공동 설계자다. "자비스를 대체할 것인가"라는 질문은 곧 **작성자 자신의 대체 여부를 작성자에게 묻는 것**이다. 자기보존 편향이 구조적으로 존재한다.
- 대응: 헤르메스의 강점을 의도적으로 최대한 강하게 기술(steelman)하고, 결론이 뒤집히는 반증 조건을 명시했다(§9). 사실 진술은 전부 외부 출처 기반이다.

**② 검색 오귀속 정정 사례 (실제 발생)**: 조사 중 "Hermes 9개 CVE 4일 만에 발견"이라는 보안 헤드라인을 확보했으나, 원문 정독 결과 **그 9건은 경쟁 제품 OpenClaw의 것**이었다. Hermes 자체 CVE는 3건(전부 Medium, 신속 패치)이다. 헤드라인만 믿었으면 헤르메스에 부당하게 불리한 보고서가 됐을 것이다 — 검색 요약 수준에서 멈추지 않고 원문을 읽어야 하는 이유.

**③ "헤르메스" 식별 확인**: 국내 기사·강의·VPS 상품까지 존재하는 화제작은 Nous Research의 **Hermes Agent**(에이전트 프레임워크)다. 동명의 Hermes LLM(모델 시리즈)과는 다른 물건이며, 본 보고서는 전자를 다룬다. 주인님이 다른 것을 지칭하셨다면 정정 필요.

## 2. 최신 헤르메스 실측 (2026-07 기준)

- **정체**: Nous Research가 2026-02 출시한 오픈소스(MIT) 자율 AI 에이전트 프레임워크. 자기 서버에 상주하며 기억하고 성장하는 "개인 AI 집사".
- **견인력**: GitHub **213,000+ 스타** (2026-07-09), OpenRouter 기준 세계에서 가장 많이 쓰이는 에이전트. 국내에도 기사·강의·전용 VPS 상품 존재.
- **최신판 v0.18.0** (2026-07-01 "The Judgment Release"): 1,720커밋/998PR, P0·P1 이슈 전량 해소, Mixture-of-Agents(다중 모델 합의), 자가 검증 목표(self-verifying goals), 백그라운드 서브에이전트 팬아웃, 네이티브 데스크톱 앱(macOS/Linux/Windows).
- **기능**: 에이전트 큐레이션 지속 메모리 + 세션 전문검색 + 사용자 모델링 / 스킬 자가 생성·개선 루프(agentskills.io 표준) / 자연어 내장 크론 / Discord·Telegram·Slack 등 20+ 메신저 통합 / 브라우저 자동화·비전·음성 / 모델 불가지론(Anthropic·OpenAI·Ollama 로컬 등 300+).
- **아키텍처**: Python 82% + TypeScript 15%. Docker/로컬/서버리스 배포.

한 줄 평: **주인님이 2월부터 손수 만들어온 자비스와 기능 스펙이 거의 1:1로 겹치는, 그러나 커뮤니티 규모가 붙은 제품**이다.

## 3. "대체"의 3가지 해석 — 범주부터 분해

"자비스를 헤르메스로 대체"는 카테고리가 다른 3가지 질문을 포함한다:

- **(A) 하네스 교체**: 수제 오케스트레이션(discord bot·claude-runner·크론 135개·MCP nexus)을 Hermes 프레임워크로 교체. ← 진짜 쟁점은 이것
- **(B) 엔진 교체**: Claude를 다른 모델로 교체. ← 별개 문제. Hermes는 모델 불가지론이라 Claude를 그대로 쓸 수 있음. (기존 룰 "외부 LLM 품질 의존 금지"와도 별개)
- **(C) 정체성/축적물 교체**: JARVIS 페르소나·위키·오답노트·가드. ← 이건 Hermes가 "대체"해주는 게 아니라 **이식하거나 버려야 하는** 대상

자비스의 실체 4층 분해:
1. 엔진 = Claude (Hermes에서도 사용 가능 → 대체 불필요)
2. 하네스 = 수제 코드 (Hermes가 대체 가능한 유일한 층)
3. 축적물 = 위키 _facts·RAG(LanceDB)·learned-mistakes 4,752건·개인화 크론 135개·13채널 페르소나 (마이그레이션 비용의 본체)
4. 관계·서사 = 페르소나, 그리고 "내가 설계했다"는 커리어 자산 (이식 불가)

## 4. 정면 비교

### 헤르메스가 이기는 것 (steelman — 정직하게 강하게)
- **개발 속도**: 월 1,700커밋의 팀+커뮤니티 vs 주인님 1인. 브라우저 자동화·데스크톱 앱·음성·MoA 같은 기능을 자비스가 따라 만들려면 각각 수 주. 격차는 시간이 갈수록 벌어진다.
- **품질 관리**: P0/P1 전량 해소 릴리즈, 외부 보안 연구자들의 지속 감사, CVE 신속 패치. 자비스는 외부 감사를 받은 적이 없다 — "폐쇄라 안전"은 검증받지 않은 안전이다.
- **표준 생태계**: agentskills.io 스킬 표준, 커뮤니티 스킬 허브, 20+ 메신저 어댑터. 자비스의 스킬·어댑터는 전부 자가 유지보수 대상.
- **이미 검증된 아이디어**: 자가 검증 목표·스킬 자가개선·서브에이전트 팬아웃 — 자비스가 실험 중인 것들(skill-loop-nightly, mistake-promoter)의 완성형이 이미 돌아간다.
- **버스 팩터**: 자비스는 주인님이 멈추면 썩는다. 헤르메스는 주인님이 없어도 발전한다.

### 자비스가 이기는 것
- **축적물 이식 불가능성**: 5개월간의 위키 도메인 사실·오답노트 4,752건·13채널 페르소나·135개 개인화 크론·면접봇·가족 채널 톤·PII 마스킹 가드. Hermes의 메모리 구조(Honcho 모델링·FTS5)로 옮기는 건 "이사"가 아니라 **재건축**이다. 마이그레이션 기간 중 회귀(이미 잡았던 실수의 재발)는 확정적.
- **비용 구조 (결정적)**: 현 자비스는 Claude **구독 OAuth**로 봇·크론이 동작한다. Hermes의 Claude 연동은 ① API 키 = 완전 종량제 ② Claude Max OAuth = **기본 제공량은 못 쓰고 "추가 구매 크레딧"만 소모**. 즉 어느 쪽이든 현재 구독료로 커버되던 사용량이 실비 전환된다. 자비스 원장 실측(분석 채널 ~$0.41/회, 1,000회/월 ≈ $410)을 대입하면 **월 수백 달러 추가 비용** 시나리오. (미검증 여지: Hermes의 `claude-code` provider 별칭이 구독 경유를 허용하는지 — 추가 확인 필요. 또한 이 경로는 Anthropic 구독 정책 변경 리스크에 노출됨)
- **프라이버시 공격면**: 자비스 1원칙은 "Data privacy comes first"다. 자비스는 가족 대화·포트폴리오(금융)·커리어 PII를 다룬다. Hermes의 지적된 공격면 — 멀티채널 인입 + **메모리 인젝션**(오염된 기억이 다음 세션에서 명령으로 실행) + **커뮤니티 스킬 마켓**(악성 스킬 지속 상주) + 기본 설정 Critical 4건(무제한 셸 등, 2026-04-11 감사) — 은 정확히 이 데이터를 노린다. 수제 자비스는 공격면이 좁고, 인입 경로를 전부 주인님이 안다.
- **커리어 서사 (개인개발의 목적함수)**: 자비스는 "RAG·멀티에이전트·가드레일을 프로덕션으로 직접 설계·운영"이라는, 면접에서 돈 주고도 못 사는 실증이다 (내일 AIP-C01이 검증하는 바로 그 역량). Hermes 설치·운영은 "사용 경험"이지 "설계 경험"이 아니다. 이력서에서 "오픈소스 프레임워크 운영"과 "직접 설계한 시스템"의 무게는 다르다. (단, 반론: Hermes 컨트리뷰터가 되는 경로는 21만 스타 프로젝트 기여 이력이라는 다른 종류의 자산이 될 수 있다.)
- **행동 가드의 깊이**: Iron Laws·검증 강제·거짓 완료 차단·감정 응답 파이프라인 같은 LLM 행동 제어는 자비스가 14턴 사고까지 겪으며 벼려온 것. Hermes의 범용 가드가 이 밀도를 대신 못 한다.

## 5. 비용 시나리오 요약

- 현행 유지: 구독료 내 (한도 공유 리스크만 존재)
- Hermes + Claude API 키: 실측 사용량 기준 월 수백 달러대 추정 (원장 $0.41/회 × 사용량)
- Hermes + Claude Max OAuth: 추가 크레딧 구매분만 소모 = 사실상 종량제와 동일
- Hermes + 로컬 모델(Ollama): 비용 0이지만 — 기존 룰 그대로 "깊이 문제를 모델 다운그레이드로 풀 수 없다". Mac Mini 사양으로 Opus급 품질 불가.

## 6. 시나리오 3안

- **A. 전면 대체**: 하네스+축적물 재건축. 이득(기능 최신성·유지보수 해방) < 손실(축적물 회귀·비용 전환·커리어 서사·프라이버시 공격면). **비추천.**
- **B. 현상 유지 + 기능 차용** (권고): 자비스 유지. Hermes에서 검증된 설계 3가지를 자비스에 이식 — ① self-verifying goals(완료 조건 자가 검증 — /goal 스킬 고도화) ② 스킬 자가개선 루프의 구조(skill-loop-nightly에 벤치마크 결합) ③ 서브에이전트 팬아웃 패턴(이미 Workflow로 보유 — 사용 빈도만 늘리면 됨). MIT 라이선스라 코드 열람·차용 합법.
- **C. 병행 실험**: 격리 환경(도커/별도 VM)에 Hermes 설치, **비민감 태스크만**(뉴스 요약·웹 리서치) 위임해 1개월 실측. 가족 채널·금융·커리어 데이터는 절대 미연결. 실측 후 B 유지 또는 부분 위임 확대 결정. (B와 병행 가능 — 주인님 시간 여유 있을 때)

## 7. 반증 조건 — 이 결론이 뒤집히는 트리거

1. Anthropic이 구독 OAuth의 서드파티/자동화 사용을 차단 → 자비스도 종량제 강제 → 비용 우위 소멸 → 재평가
2. Hermes가 구독 기본 제공량 사용을 공식 지원 → 비용 격차 소멸 → 재평가
3. 주인님의 유지보수 가용 시간이 구조적으로 붕괴(이직 후 등) → "버스 팩터" 항목의 가중치 급상승 → C안 확대
4. Hermes가 메모리 암호화 + 스킬 서명 검증 + 최소권한 기본값을 달성 → 프라이버시 반대 근거 약화
5. 자비스 핵심 인프라의 반복 장애로 신뢰 붕괴 → 재건축 비용 논리 역전

분기 1회(10월 초) 이 5개 조건 재점검을 권고.
